## 2. 根因（一句话）

联盟榜表格行打开详情时，标题点击安全校验按选品广场卡片（`__cardContent___` / 笼统 button-closest）设计，把行内标题误判为落在加车或非本商品控件内并 `raise RuntimeError`；上层又因文案含「商品 ID」把**单品**失败升级为**整批安全停机待核查**，导致无法跳过继续选下一候选。

## 3. 最小修复方案（只动本缺陷相关；优先 `engine/browser_cdp.py`）

### 3.1 正确点标题 / 打开本商品详情（业务规则 1、4）

改 `_click_candidate_detail_target`（及若必要的极小辅助函数，仍在同文件）：

- **保留**卡片路径：有唯一可见 `__cardContent___` 时现有逻辑可继续。
- **新增联盟/表格行路径**（行根为 `tr` / `[role=row]` / 无可用 `__cardContent___` 时）：
  1. 在**已按商品 ID 复核过的同一行**内，定位「商品信息」侧标题（exact 标题文本，或行内标题节点），**明确排除「操作」列 / 含「加车」「加入选品车」等按钮**。
  2. 点击目标必须是本商品详情入口（标题文本节点、商品信息区、或确属本 productId 的链接），**禁止**把操作列加车按钮当成详情点击。
  3. `closest('button')` 校验要区分：操作列加车按钮 vs 标题自身可点容器；勿因行级可点结构误杀标题。
  4. 若标题节点被判定不安全，先在同 ID 行内找替代安全目标（商品信息区标题 / 主图旁标题链接）；仍无安全目标再视为**本商品**点击失败（见 3.2），不要误点加车按钮「碰运气」。
- 点击后仍依赖现有 `pack_detail` 商品 ID 校验，避免串品。

### 3.2 单品失败跳过，禁止整批安全停机常态（业务规则 2、3）

- 「标题位于加车或非本商品操作控件内，未点击详情」这类**在列表仍可按商品 ID 唯一定位、页面未跑飞**的情况，应走与 `CandidateDetailClickBlockedError` 同类的**单品跳过**：
  - 标记 `_detailClickSkipped`（或等价），记入 rejected/skipped，**continue 下一候选**；
  - **禁止**再被 L8486–8489 的「商品 ID」宽泛匹配包装成「触发安全停止」整批待核查。
- 实现建议（择一，保持最小）：
  - A：此类失败改抛 `CandidateDetailClickBlockedError`（复用已有 skip）；或
  - B：收窄 L8486–8489：仅对真正身份不确定 / 账号风控 / 无法返回列表等 pause；**单品标题落点/详情打开失败不得因文案含「商品 ID」就整批停**。
- 真正必须停机的情形保持 fail-closed（手动验证、登录失效、列表无法返回、多卡身份冲突等）——但**不得**把「单品标题点不开」算作常态安全停机成功标准。

### 3.3 保留并完善唯一定位（业务规则 4）

- **不要回退**上一轮：`BAIYING_PRIORITY_ALLIANCE_ROW_SELECTOR`、`_locate_candidate_card` 行选择器、`_wait_for_priority_source_candidates_ready`、`_execute_visible_source_candidates` 等待调用。
- 若标题点击新路径依赖行定位，确保与上述选择器一致（`tbody tr` / `__row___` / `__card___` 等）。

### 3.4 不要做

- 不要 push / 打包 / 删除 / 登录验证码 / 清 UNCERTAIN / 指导重复选上述两枚商品
- 不要大范围重构选品策略 / 无关 UI
