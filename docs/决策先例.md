# 决策先例库

> 用途：记录守门员拍板与纠正，供新会话与授权分级（A/B/C）引用。  
> 维护：主对话每次拍板后追加；文档管理员可协助整理。  
> 格式：场景 / 我的决定 / 我的理由 / 日期

---

## 授权分级摘要（2026-10-29）

- **A 级·可自主**：先例完全一致 → 直接做，日报报备。
- **B 级·先斩后奏**：相似先例但参数不同 → 可做，做完立即单独报备；修正回流本库。
- **C 级·必须请示**：无先例 + 五道闸门事项。
- **永不下放（永远 C）**：合规红线、凭证账号、不可逆操作。

五道闸门：需求 / 方案 / 凭证 / 不可逆 / 验收。

## 先例条目

### P-2026-11-19-千川商品全域投放计划页上传
- **场景**：原客户端把千川流程写成先进入素材库再上传，与用户提供的商品全域投放录屏不一致。
- **决定**：进入商品全域投放后先选投放商品（精确商品 ID），选择“控成本投放”；在“自选投放素材”再次选择同一商品，再点“添加视频”。本地 MP4 在计划页“上传视频”页签逐件上传；已发布作品可从“我的视频”选择。预算与保本 ROI 在提交前确认；结果不明先回读，不盲目再次提交。只有取得唯一千川计划 ID 才算发布成功。录屏选中过“放量投放”，但本次明确决定以用户最新确认的“控成本投放”为准。
- **状态**：A 独立工作树源码已改；未运行类型检查、测试或真实千川验收。录屏没有展示上传页签内部与最终提交，相关控件和回执待实页校准。

### P-2026-11-19-部分候选池长期保留与续采
- **场景**：候选池尚未达标时可能因手动暂停、网络错误、11001、客户端退出或结束旧批次而中断；用户要下次在已存商品基础上继续，不从零开始。
- **决定**：每个已完成浏览器命令的已确认候选及游标立即落入本机批次检查点；命令未返回的结果不视为已保存。原批次继续读取原检查点；结束后新批次合并本机多个未达标或已达标池，按采集时间从新到旧、商品 ID 去重，只搬运候选发现数据，不搬运采集游标、账号配额、加车或发布状态。商品 ID 长期保留可查看。与当前筛选、来源权限、类目树及采集账号资料一致且采集未超过 24 小时的行可按现有校验直接计数；超过 24 小时或设置、采集账号变化的旧 ID 仅为优先线索，须在当前采集账号和当前来源页面重新确认商品、筛选、类目、排除及防重后才计入池；未找到或无法确认则保留旧记录但不计数，继续按原规则补采。网络错误、11001 与暂时无新增按已保存检查点退避续做；手动暂停、登录、验证码、安全验证及来源结果不明保留安全停点，须人工处理。已落盘候选不能被刷新设置路径静默清空。候选池数量不代表加车或发布成功。
- **状态**：A 独立工作树源码已改；未运行类型检查、隔离测试、客户端或真实百应验收。

### P-2026-11-19-消费账号搜索 11001 网络提示短重查
- **场景**：消费账号按候选池商品 ID 搜索时反复收到百应业务码 11001；客户端旧逻辑仅凭码值称为限流并固定从 60 秒起等待，原始平台提示没有进入该步骤的日志。历史同接口出现过“当前网络不稳定，请稍后再试”，不能把 11001 等同于真实限流。
- **决定**：只调整消费账号按精确商品 ID 的只读搜索。平台原始提示明确为网络错误、且未提示频控时，等待 5 秒对同一 ID 最多重查一次；仍返回同类错误或重查结果未确认，就在加车前停止本轮、保留检查点，30 秒后自动续做，连续失败按 30/60/120/240/480/900 秒逐步退避，确认加车成功后重置连续次数。原始提示明确频控或缺失时保留旧的 60 秒起保护等待；第二次响应若变成频控或提示缺失，也按该保护路径。仅记录脱敏的 HTTP 状态、业务码、平台提示等必要诊断；用户可见日志区分网络提示、频控及原因未确认。旧批次检查点和手动暂停守卫保持有效；候选池采集的 11001 策略不变。
- **状态**：A 独立工作树源码已改；未运行类型检查、测试、客户端视觉验收或真实百应验收。

### P-2026-11-19-全客户端适度紧凑布局
- **场景**：浅色界面已统一，但商品和素材展示占用空间较多，用户希望一屏看到更多内容。
- **决定**：在现有浅色留白、深色文字和少量蓝色强调的规则上，将全客户端标题、控件、卡片及间距适度收紧约 10%–15%，商品与素材列表优先提高单屏可见数量；不整页缩放，不降低正文可读性。保留商品 ID、来源、状态等关键字段；长标题最多两行，完整文字可查看。后续页面也沿用此密度节奏；“暂停选品”“结束上一批次”等关键操作继续保持醒目。
- **状态**：A 独立工作树源码已改；未运行类型检查、测试、客户端视觉验收或打包。

### P-2026-11-19-手动安全暂停选品
- **场景**：正式选品可能在共享候选池采集、逐账号加车和发布之间持续运行；用户需要明显的暂停入口，也需要明显地结束上一待恢复批次。
- **决定**：选品页顶部显示醒目的“暂停选品”；用户点击后立即显示等待安全暂停，当前浏览器命令返回并保存结果后，在下一轮采集、下一件商品或下一个账号前停止，关闭该账号浏览器，保留检查点。当前命令内可能已经处理多件商品，不强制杀进程或将不明加车、发布结果判为成功。手动暂停状态跨重启保存，候选池退避、11001 冷却和每日定时任务都不得恢复该批次，直到用户明确点击“继续选品”；其他批次和已保存任务不受影响。待恢复批次顶部显示醒目的“结束上一批次”，沿用原确认、状态守卫和检查点保留，不将批次标记成功。界面沿用浅色设计及语义色。
- **状态**：A 独立工作树源码已改；未运行类型检查、测试、客户端视觉验收或真实平台验收。

### P-2026-11-19-共享候选池优先进度
- **场景**：正式选品已改为先建立或复用共享候选池，但原进度卡仍按旧账号八阶段流程显示采集权重和账号进度，无法直接看到候选池是否达标。
- **决定**：正式批次先显示共享候选池进度，以本批次已保存的唯一商品数/目标数计算池比例；配额模式展示来源及类目规则的已存数、有效目标和缺额。池未达标时不显示消费账号阶段；池达标后在上方保留完成摘要，下方显示逐账号核验、加车、视频和发布队列/自动发布阶段。历史池复用、自动续采和重启读取同一检查点，只有落盘确认后更新已存量。账号阶段百分比注明按阶段估算，候选池达标不代表加车或发布成功；候选预览独立，旧批次无共享池时沿用原流程。界面遵循已确认的浅色设计变量。
- **状态**：A 独立工作树源码已改；未运行类型检查、测试、客户端视觉验收或真实平台验收。

### P-2026-11-19-候选池商品详情只读弹窗
- **场景**：用户希望点击候选池商品后，在弹窗中查看该商品的详细信息；现有历史池只预览前 20 件商品 ID 与名称。
- **决定**：当前批次检查点、当前预览候选和本机历史池均提供商品详情入口。历史池内全部商品可按商品 ID 或名称搜索、分页查看，再点击打开弹窗；现有历史池卡片仍展示最近 3 个池。弹窗只展示本机已保存的业务字段，按基本信息、经营指标、来源与类目、采集与分析分组；缺失字段标“未采集”，不展示原始诊断数据，也不为查看详情访问百应。详情为只读快照，不代表消费账号已核验详情、加车或发布。界面沿用已确认的浅色设计规则。
- **状态**：A 独立工作树源码已改；未运行类型检查、测试、客户端视觉验收或真实平台验收。

### P-2026-11-19-客户端及后续功能统一浅色设计
- **场景**：现有 Electron 客户端页面和弹窗视觉规则不一；用户要求参照苹果官网的清爽排版优化整个客户端，并要求今后功能保持相同设计思路。
- **决定**：所有现有页面、弹窗和后续新功能均以浅色留白、深色易读文字、少量蓝色强调为基调；使用 `main.css` 的语义颜色、间距、圆角和阴影变量，统一标题层级、导航、表单、按钮、卡片、表格、状态提示及焦点反馈。保留现有运营信息量，以分组和间距提高可读性；错误、风险、成功仍用各自语义色，不能只靠颜色传达状态。适配 Windows 客户端常用及较窄窗口，不照搬苹果品牌元素。后续功能开发和评审按本条执行。
- **状态**：A 独立工作树源码已改；未运行类型检查、测试、客户端视觉验收或打包。

### P-2026-11-19-商品视频高度相似才跳过
- **场景**：按商品 ID 下载或加车后自动下载同款带货视频时，不同视频 ID 可能对应画面高度相似的作品；仅按 ID 或文件哈希去重会把它们全部保存。
- **决定**：同账号、同商品的视频只有抽样画面按时间顺序达到明确的高度相似阈值时才跳过；本次下载入口采用 80% 重合阈值。同一人出镜、同一商品但拍摄内容不同，不能仅凭人物相同判重。新候选先进入临时区，确认不相似后才放入正式商品目录并登记素材库；相似项记录原因、不计自动下载目标数，继续下一条。识别结果不明时保留并提示复核；已有文件不自动删除。千川素材后续筛选的既有 60% 阈值保持原义。
- **状态**：A 独立工作树源码已改；未运行测试、真实下载、客户端界面或打包验收。

### P-2026-11-18-热点仅按一级分类采集
- **场景**：真实热点趋势页只有一级分类按钮；通用类目计划在排除二/三级时生成下级路径，使热点来源无法选中并回读。
- **决定**：热点逐个点击当前页面可用的一级类目，跳过已排除的一级。若某一级下有任意二级或三级排除项，热点整支跳过该一级；其他来源可用更深的页面筛选承担缺额。热点不允许设置二级或三级正向配额，也不允许为含下级排除项的一级设置热点配额；旧批次含深层热点配额时明确阻止按新逻辑续采。按钮名称仅可在当前百应类目树和页面按钮均唯一时辅助定位，入池仍须核对实际请求中的一级 ID、按钮选中状态及该分类下的商品结果；不能确认则不计入池。恢复时保留已确认入池商品，只重置热点受影响游标并按 ID 去重。
- **覆盖关系**：热点来源按本条覆盖 `P-2026-11-18-类目一级优先与二级分支排除` 中“有下级排除时点击未排除的二级兄弟类目”的做法；榜单和选品广场仍执行原规则。
- **状态**：A 独立工作树源码已改；未运行检查、测试或真实百应验收。点击后请求是否可回读一级 ID、真实新增商品与限流后的续采均待确认。

### P-2026-11-18-三来源分别设定候选数量
- **场景**：单一候选池总数目标无法保证热点趋势、联盟榜单和选品广场分别贡献多少合格商品，用户要求在软件内直接填写各来源数量。
- **决定**：在现有来源/品类配额模式提供三个来源合计目标输入，指定品类配额计入所属来源，剩余量由该来源全部允许类目规则承担；只有移除该来源指定品类配额后才能将来源目标设为 0。所有规则目标之和为总池目标，保存和启动时仍须覆盖消费账号目标之和。采集账号串行，同一账号内按规则顺序轮流读取，每轮每条规则一次；每条规则独立记录分类游标、目标、已采集、缺额。商品只有通过当前筛选、页面类目回读和跨规则商品 ID 去重后才计数；同一商品按规则顺序归属首个仍缺额的规则。来源确认耗尽并经过正常退避补读后，缺额按原决定转给其他规则，并如实显示转入、转出；不能放宽佣金、类目排除或其他条件。旧批次仍按原快照恢复，不将新输入倒灌旧批次。
- **覆盖关系**：补充 `P-2026-11-18-完整选品发布共享池与离线登记恢复` 的配额输入形式；保留其中的缺额转移、账号串行、精确详情与发布回执要求。
- **状态**：A 独立工作树源码已改；未运行检查、测试或真实百应验收。三来源达到各自目标及浏览器超时仍待真实环境确认。

### P-2026-11-18-类目一级优先与二级分支排除
- **场景**：通用候选池在仅排除一级类目时仍逐个点击数百个三级类目；用户要求按真实选品设置缩短分类操作，并让热点、榜单、选品广场都参与采集。
- **决定**：三个已启用来源按设置顺序轮流采集、跨来源按商品 ID 去重并补足总池目标。排除一级就跳过整棵根；排除二级就跳过该二级整支；排除三级先用当前百应类目树唯一定位其二级父类目，再跳过整支二级。一级下没有有效下级排除时只选择一级；有下级排除时先进入一级，再逐项选择未排除的二级兄弟类目。只有用户明确设置二级或三级正向配额时才按目标深度下钻。须回读当前页面的分类状态与对应列表请求；选品广场以请求中的精确类目 ID 及其返回列表为最后入池证据，热点和榜单还要核对来源分类状态。无法确认的路径不计入池，也不使用“全部”页代替。旧批次保留已确认入池商品，只重置受本规则影响的分类游标，按商品 ID 去重续采。
- **覆盖关系**：覆盖 `P-2026-11-18-候选池先应用页面类目筛选` 中“下级排除展开至允许的末级路径”的实现层级；保留该条关于页面证据、精确商品 ID、冲突拦截和消费账号详情核验的要求。
- **状态**：A 独立工作树已补采集、设置与候选池保存层源码；新行须有页面来源路径，旧池已确认商品按 ID 保留。未运行检查、测试或真实百应验收。一级入口能否直接筛出目标 ID、热点二级分类是否可稳定回读，仍须实页确认。

### P-2026-11-18-候选池先应用页面类目筛选
- **场景**：真实批次热点读取 68 件却有 49 件因商品详情缺类目被拦；用户再次明确选品顺序是先在百应页面按设置选择类目，再从该筛选结果收集商品 ID。设置二级、三级类目时也应先应用对应层级，而不是要求每件商品的响应再次返回 `categoryIds`。
- **决定**：候选入池的类目归属来自已回读的页面分类 ID 路径及该筛选下读取到的精确商品 ID。先排除禁选路径，再按设置选择允许的一级、二级或三级路径；若上级路径覆盖了更深层的排除条件，就展开并分别读取允许的下级路径。分类控件、选中状态、路径 ID 或筛选后的列表结果无法确认时，该来源本轮不计入池。`categoryIds` 作为商品行可选字段，不作为逐件入池条件；已确认的来源路径单独保存在 `sourceCategoryIds`，商品行若明确返回与之冲突的类目仍须拦截。佣金、体验分等条件继续按实际数据核验。消费账号仍打开详情核对精确商品 ID、必要指标和加车结果；商品详情缺少类目字段本身不否定采集时已确认的筛选路径，但当前账号另有更深的排除/品类条件且来源路径不足时不能加车。
- **覆盖关系**：本条覆盖 `P-2026-11-15-02` 的“商品必须取得完整三级类目才可加车”以及 `P-2026-11-16-三来源候选池筛选` 中只允许一级来源类目入池的限制；仍保留不能凭分类名称猜 ID、不能使用未生效筛选或错商品 ID、不能放宽排除条件的要求。
