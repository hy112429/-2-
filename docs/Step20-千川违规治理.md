# Step 20 · 千川违规素材治理

## 范围

在「千川素材上传」页选择已绑定的千川账户，打开专属浏览器并登录后，读取页面中判定为违规、劣质、低质、不合规或审核未通过的素材。显示名称、千川素材 ID、判定、原因和检测时间。读取不需要先上传新视频。

## 删除流程

1. 完整读取素材列表并翻页。只有页面存在唯一的 `data-material-id` 或 `data-creative-id`、且独立状态单元格明确显示违规判定的行可勾选。没有唯一 ID 的行仅供查看。
2. 选择最多 50 条，生成 SQLite 删除批次和本机 UTF-8 BOM CSV 清单。界面可另存 CSV。读取结果超过 30 分钟须重新扫描。
3. 界面先显示待删条数和完整清单，再要求二次输入「删除 N 条」；主进程重新核对批次和数量。
4. 同一千川账户的上传和治理共用互斥锁。逐条定位远端 ID、复核违规状态、点击该行唯一删除控件及平台唯一确认框，刷新并遍历列表核验结果。进度逐条回传。
5. 点击前的登录或定位失败记为 `failed`，重新扫描后可生成新清单重试。点击后结果不明确、网络中断或客户端中途退出时，项目标为 `needs_review` 并停止本批后续删除；禁止自动重试同一远端 ID。失败截图和原因保存在本机，事件写入 `qianchuan_violation_events`。历史批次可回看。

删除是平台不可逆操作。源码选择器按唯一身份与状态收紧；千川真实页面 DOM 尚未校准，因此无法保证现阶段真实页面会返回可删除行，遇到未知结构会停止。浏览器自动化方案复用 Step 11/17 的 `qianchuan-{账户ID}` 专属 Chrome，不使用开放平台凭证。

## 本轮验证与待验收

隔离测试 5/5，覆盖不完整扫描拒绝准备、清单留档、待核查素材禁止重复提交、无唯一 ID 不准入、中断隔离及缺少远端行时不点击删除。Python 语法检查和桌面 TypeScript 类型检查通过。未登录真实千川、未拉取真实违规列表、未执行平台删除、未打包。真实验收需要已登录的专用千川账户及账号内已有的违规素材；先核对页面字段和删除回执，再在明确指定的测试素材上执行删除。
