# 多账号选品按账号顺序使用浏览器

- 日期：2026-11-09
- 来源：用户确认的多账号选品流程调整
- 状态：源码已调整，`npm run typecheck` 通过；客户端实机与安装版验收待做
- 适用：选品新批次和待恢复批次

## 确认要求

启用多个账号时，客户端不能在批次正式执行前逐个打开所有账号的百应和创作者中心页面。按账号顺序完成工作：只打开当前账号的专属浏览器，完成该账号的登录检查、选品、加入选品车、商品素材处理和发布处理后关闭该浏览器，再启动下一个账号。

批次账号清单、账号设置、profile 路径和下载路径可以提前在本地核对；这些只读准备不能启动各账号浏览器。候选采集也应在轮到当前账号时执行，不预先遍历后续账号。

## 登录、失败与恢复

- 轮到某账号后，先检查该账号专属 profile 中的百应和抖音创作者中心状态；登录态通过后沿用当前窗口完成该账号流程。
- 若需要登录或人工验证，保留当前账号窗口供用户处理，暂停后续账号，不启动其他浏览器。用户重新检查并继续批次后，从该账号检查点接续。
- 若百应限流，保存该账号的候选查询恢复状态并暂停后续账号，等待冷却或用户恢复。
- 当前账号流程结束后关闭客户端管理的该账号 Chrome 窗口，保留 profile、Cookie 和登录态。确认窗口关闭后才处理下一个账号。
- 如果窗口未能关闭，保留批次并暂停后续账号，避免多个账号窗口累积。恢复时先处理此前已完成账号遗留的客户端浏览器窗口，再继续队列。
- 账号任务出现可恢复商品问题但本账号流程已经结束且浏览器成功关闭时，记录该账号的部分完成状态并继续下一个账号。

## 候选互斥

不再依赖启动时预读所有账号的候选池来分配商品。候选池只在当前账号开始时采集；本机全局商品登记和原子预留继续阻止同一商品被多个账号重复处理，并保留已有重复登记、配额和发布锁规则。

## 验收范围

源码调整不等于真实验收。验收需至少使用两个账号确认：启动时只出现第一个账号的浏览器；其选品和发布处理结束后窗口关闭；之后才出现第二个账号的浏览器。另需确认登录检查失败或窗口关闭失败会暂停后续账号，且继续批次不会重复加车或发布已经完成的商品。安装版需在重新打包后另行验收。
