## 0. 使用说明（先看这段，很重要）

### 0.1 核心节奏

**一次只跑一步。** 跑完 → 自己验证 → 通过了再发下一条。不要把 10 步一口气全丢给 AI。

| 原则 | 说明 |
|---|---|
| 一步一验收 | 每步都有「✅ 验收标准」，不通过不往下走 |
| 先验风险，后搭界面 | Step 1–2 是**技术预研**，先把最可能失败的事验证掉，再写界面 |
| 用报错对话 | 不会调试没关系，**把完整报错原样贴给 AI**，让它定位 |
| 会话会变长 | 上下文太长时，让 AI 先输出「当前进度摘要」，然后**开新会话**把摘要 + 开场 Prompt 一起发 |

### 0.2 标准工作流

```
发【开场 Prompt】→ 发【Step N Prompt】→ AI 给方案+代码 →
你执行 → 成功：进入 Step N+1 ／ 失败：贴报错 → AI 修 → 再执行
```

## 5. 用 AI 的几条禁忌（新手最容易踩）

| 禁忌 | 后果 | 正确做法 |
|---|---|---|
| 一口气让 AI 写整个项目 | 代码越多越失控，出错了不知道从哪查 | **一步一验收** |
| 不看代码直接复制运行 | 出错时完全无法定位 | 至少让 AI 逐段解释关键逻辑 |
| 让 AI 换技术栈 | 前面积累全部作废 | 技术栈已锁定，不许改 |
| 报错只贴一句"报错了" | AI 只能瞎猜 | 贴**完整**报错 + 执行命令 + 环境 |
| 会话无限延续 | 上下文过长后 AI 开始忘事、乱改 | 及时输出进度摘要，**开新会话** |
| 做完不跑就往下走 | 错误层层累积，最后无法收拾 | 每步必跑、必验收 |

5. **Step 16 发布验收**：按 A-66/A-68/A-71，全自动默认开启，发布页不提供启停开关；配置升级只初始化一次，保留最大队列 ID 边界，旧任务不追溯。每个商品视频生成入队后立即按任务 ID 唤醒发布器，发布阶段逐商品串行；配额不足仍顺延。每次只执行 scheduled 且 not_uploaded 的合格任务；A-63 遗留状态按 A-79 隔离，不阻塞后续任务。待核查记录保持原状态，不自动重试或标记成功。已排期全自动计划可由用户二次确认后单条马上发布；此入口只跳过计划等待和全局自动开关，不改全局设置，并在数据库事务内重验账号状态、队列边界、A-63 阻塞、A-64 商品锁和 A-70 当天配额。图转视频选品任务上传队列保存的 9:16 本地 MP4；作品标题使用关联商品名，按页面上限（默认 30 字）截取；商品短标题从商品标题与作品简介提取关键词组合，按页面上限（默认 10 字）填写，不再截取商品名开头。自动化填入后必须回读核对作品标题、商品短标题、简介、商品关联、视频文件名；使用创作者中心 AI 推荐封面，提交前确认至少一个推荐封面处于选中状态，无选中时选择第一张并确认，不上传自定义封面，封面状态无法确认时不得提交。人工发布计划与「发布」入口仍可用，提交结果不确定时锁定、禁止重试并人工核对。真实发布资质须在当前账号的专属浏览器页面确认，本地构建不代表平台通过；遇资质、验证码、购物车选项或结果不确定须停下，不绕过、不自动重试。
6. **看板范围**：现有本地运营工作台/队列概览不等同于 SRS FR-D1-01 的完整投放看板；未完成千川广告明细、指标和数据链路验收前，不将 D 模块标为完成。
7. **选品失败处理（A-53）**：允许跳过并继续的错误必须有明确类目/商品对象和失败阶段，写入批次日志与可恢复检查点；平台或本地状态有不确定性时必须停批。被跳过的候选不得在恢复批次中再次加车。
7. **选品过程日志（测试阶段诊断扩展）**：自动选品批次按批次、账号、商品和阶段追加记录开始/结束、候选入选、数据筛选跳过、加车成功或失败事件；每条商品事件显示真实记录时间、商品名和 ID、阶段、结果及简短说明，错误码与脱敏后的自动化诊断可展开查看。日志按成功、提示/跳过、失败分类；账号和批次摘要同时记录完成数量及待恢复状态。恢复时保留历史事件，日志写入失败不得中断选品。继续使用本地 `selection_run_logs`，不新增数据库结构；仅展示检查点已保存的旧错误，不为旧批次补造没有记录的成功事件时间。日志仅用于当前联调，不替代 Step 14 的正式全流程日志，不记录 Cookie、令牌或响应正文。

### 工程补充 A-79：单项发布异常隔离（2026-10-26）

单个发布任务失败时，先写入既有安全状态并隔离：上传前阶段为 `needs_review`；上传后尚未明确点击最终发布为 `uploaded_waiting_publish`；最终提交已尝试或结果不明为 `submission_uncertain`。发布器只选择 `scheduled + not_uploaded` 的合格任务，待核查任务不会被自动重试或自动标记成功，也不阻止其他合格任务。检查点保存成功后继续队列；队列不可读取或检查点写入失败时仍可暂停全局调度以防重复执行。选品批次中一件商品发布失败只写失败日志并继续处理其余商品；失败队列记录不把已完成选品批次改成待恢复。发布页继续不提供全自动启停按钮；“马上发布”仍需检查待核查任务。

### 工程补充 A-92：购物车标签和商品链接控件识别（2026-10-27）

自动投稿必须在**当前任务账号的专属 Chrome profile** 中判断购物车入口，不得以其他账号或普通浏览器截图代替。若当前投稿页已选择购物车，应在该标签区域唯一定位商品链接输入框；空框可由同一区域的「购物车」和「添加链接」上下文识别。若尚未选择，展开「添加标签」并检查可见选项；确无购物车时，记录投稿路径和实际可见选项，停止关联与发布，供用户核查该账号的登录身份、权限和页面状态。不同账号在同一路径可能显示不同选项，不得自动绕过缺失入口。

「添加链接」可能是与链接输入框同父的可点击 `span`，不能只按 `button` 角色定位。输入框必须与唯一的同父「添加链接」控件对应，不能仅凭整个表单的祖先文字识别；填写前先核验控件可用。点击后按 A-93 完成平台要求的商品短标题编辑，再从当前购物车区域核验目标商品 ID 或完整名称；页面通用「添加成功」提示不能单独证明关联成功。核验通过后才能继续核对发布选项和提交。既有待核查任务不得因选择器更新而自动重试或重复上传。

### 工程补充 A-93：添品后先完成商品短标题编辑（2026-10-27）

部分创作者中心页面在点击「添加链接」后，先弹出必填的「编辑商品」窗口；商品短标题未填并点「完成编辑」前，购物车商品卡片和关联回读不会出现。此时执行顺序必须是：核验商品链接→点击唯一添品控件→等待并核对当前商品的编辑弹窗原始标题→填写并回读不超过页面 `maxlength`（默认 10 字）的短标题→点击「完成编辑」并确认弹窗关闭→核对卡片短标题和本次商品 ID/完整名称关联→再检查发布设置并提交。若旧版页面先显示已关联商品卡片，则从该卡片唯一「编辑」入口填写短标题。错商品弹窗、短标题未保存或关联未确认都不得点击发布；已上传待核查任务不得因修复自动重传。

同账号有多个投稿页时，恢复或人工最终提交必须唯一定位到队列对应的上传页面；仅凭“最后一个标签”、相同商品标题/简介/链接或可见视频预览不足以证明唯一身份。零页或多页匹配都停在待核查，先人工核对草稿和平台状态，不重新上传或发布。

### 工程补充 A-94：AI 推荐封面提交前确认（2026-10-27）

图转视频自动和手动发布准备均需在当前账号创作者中心投稿页处理封面。视频上传和商品关联后，等待唯一可见的「AI智能推荐封面」候选区（最多 60 秒）；检测到已选封面时保留平台当前选择；没有选中项时选择第一张可见 AI 推荐封面，并从候选卡片的选中状态、勾选标识或选中边框回读确认。候选不足两张、选中状态歧义或点击后无法确认时，停在最终发布前。只使用平台为视频生成的 AI 推荐封面，不上传或生成本地封面图。最终人工提交路径也重复确认封面；既有待核查任务不自动恢复、重传或提交。

### 工程补充 A-104：本机重复候选自动补位（2026-11-02，源码未验证/未打包）

正式选品在本机原子预留阶段遇到已登记商品 ID 或末级类目冲突时，应记录被跳过候选并按既有排序继续预留后续候选，不因去重冲突暂停整批。普通自动模式从完整已筛快照补位，单轮最多检查 30 个候选；原子预留最多为目标加车数的 3 倍（目标上限 10），多账号分配也须为替补候选保留互斥容量。预留幂等复用必须匹配同一请求 ID，不能让并发批次共用预留。只有实际执行返回的商品才按加车结果结算；命令正常结束但未处理到的备用预留释放为未加车。恢复批次不跨出恢复快照，人工调整预览勾选不使用未勾选候选。曾点击加车而回执不确定的商品必须保持待核查且不可再次点击。若百应已经确认加车，之后素材目录创建的权限异常只记作素材下载失败，不能改写加车结果并锁住整批。
