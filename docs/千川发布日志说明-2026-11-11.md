# 千川发布日志

## 用途

千川计划页负责创建和发布计划；“更多功能 → 千川发布日志”只读展示每条计划的完整过程。它参考选品日志的“历史记录 + 详情时间线”结构，用来判断任务卡在哪一步，不会因为刷新日志而再次发布。

## 记录内容

每条计划会按时间写入以下事件：

1. 生成待发布计划：记录商品 ID、计划来源、日预算和保本 ROI。
2. 开始提交千川：记录广告主 ID、预算、ROI 和本地素材数量。
3. 发布成功：记录平台返回的千川计划 ID。
4. 待核查：提交结果不明确、客户端中断或浏览器没有可信回执时，记录原因并停止自动重传。
5. 发布前停止：预算、佣金率、素材或账号条件不满足时记录阻止原因。
6. 人工核查、重新排队：保留人工确认的依据和恢复动作。
7. 追加素材：记录次日补入原计划的开始、成功、已存在、待核查和停止结果。

日志只保存任务元数据、错误说明和诊断截图路径，不保存 Cookie、Token 或请求正文。

## 使用方式

- 进入“千川投放”，点击右上角“发布日志”，或在“更多功能”中打开“千川发布日志”。
- 左侧按账号、计划状态和日期筛选历史计划。
- 点击计划查看预算、ROI、商品 ID、广告主 ID、远端计划 ID 和过程时间线。
- “待核查”表示结果未知，先到千川页面核对计划是否存在，再在千川计划页录入人工结论；不要直接重复提交。

## 实际验收边界

代码和隔离构建已验证日志表、查询接口和页面编译；没有使用 B 电脑的真实千川登录态执行付费计划。真实验收时应至少验证：生成草稿、提交开始、成功回读计划 ID、提交不明转待核查、重启恢复和人工核查结论均能在日志时间线中看到。

## 2026-11-12 自动队列行为补充

- 账户已开启自动计划并保存日预算后，自动任务按待发布队列串行执行；每项完成后继续下一项，不再人为等待下一分钟调度。
- 后台优先使用已打开的对应千川/抖音专属浏览器；若未打开，只有检测到已有 `Default` 用户资料时才会自动启动。没有可复用资料时，任务仍为“待发布”，详情原因会提示先建立并登录账号浏览器。
- 自动计划提交结果不明时进入“待核查”，暂停同一千川广告主的后续计划；其他广告主不受影响。核对前不重试，避免重复创建投放。
- 这只是代码行为说明。本轮未执行类型检查、隔离测试、构建或真实千川发布；需要在 A 端专用账号验收后再更新结果状态。
