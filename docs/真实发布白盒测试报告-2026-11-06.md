## 本轮发现并修正

1. 发布队列的两个旧用例仍期待人工确认；当前实现已明确将新生成视频排为 `scheduled` 自动任务。更新断言，并在 CLI 测试前提交测试连接，避免 SQLite 锁造成假失败。
2. “其他商品行隔离”用例自造残缺发布队列表，缺少当前源码使用的 `screenshot_path` 等字段。改为使用正式 `ensure_schema()` 创建测试表。
3. Step 17 素材归属用例只能从项目根包方式导入；补上从 `engine` 目录运行时的导入方式。
4. 千川 OAuth 授权列表只有工作台管理身份、但查不到其下千川广告主时，原逻辑返回“不需千川授权”。改为明确提示缺少可用广告主，并补模拟用例验证空列表与成功发现列表。
5. `ProductQueryView.vue` 视频编辑事件类型缺少实际使用的 `taskId`，导致 `vue-tsc` 不通过；补齐事件类型后构建通过。

## 全仓补修

首轮全量 Python 310 项有 11 项失败、5 项报错；桌面脚本有 5 个失败项。逐项核对源码后确认，失败集中在测试仍按旧的双源候选、旧卡片 HTML 判断、共享登记服务及旧文案写断言。修复时保留了安全行为检查：同名商品按 ID 唯一定位，不确定加车只跳过当前商品；来源读取异常不会伪造候选；本机登记不访问共享服务。

- Python：更新 `test_browser_cdp_recovery.py` 的三源读取返回值、商品 ID DOM/React 模拟、来源预检替身和跳过状态断言；更新 `test_selection_recommendations.py` 的三源函数签名、统一分加分后的预期，并隔离报告写盘。
- 桌面：补齐 `external_browser_retry.test.mjs` 的 `app-dirs` 测试替身；把 `selection_registry_adapter.test.mjs` 改为当前本机 SQLite 登记契约；更新 `selection_candidates.test.mjs` 的现行原因文案。
