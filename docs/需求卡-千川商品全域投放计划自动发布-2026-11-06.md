# 千川商品全域投放计划自动创建与发布 · 2026-11-06

## 用户已确认的范围

这是一项新的**付费投放计划**功能，与 Step 17 的“把本地 MP4 上传千川素材库”不同。用户明确要求客户端自动完成“创建并发布投放计划”，正常任务不逐条弹确认。

- 触发：同账号同商品的抖音作品确认 `publish_queue.platform_status=published`，且所选视频素材就绪。
- 日预算：每个千川账户单独配置；无预算或未启用时不能创建计划。
- 视频来源：支持已发布的抖音主页作品、Step 17 已上传的本地 MP4，也可选两种来源。
- 初始选项：放量投放、从今天起长期投放、智能优惠券开启、AIGC 关闭。账户配置中优惠券与 AIGC 可以改；投放方式和时段的其他选项尚无可验证的页面参数，本轮执行器只处理这组已确认选项。
- 提交前核对：唯一抖音账号与千川档案绑定、页面广告主 ID、商品 ID、已选素材、日预算和计划名称。点击“发布计划”最多一次；远端计划 ID 未明确回读则待核查，不自动重复提交。

## 当前实现

- `engine/qianchuan_plan.py`：按千川账户存设置；同千川账户、抖音账号、商品 ID 只建一条计划任务；旧发布记录不追溯；Step 17 MP4 来源等待同账号同商品的成功上传记录和远端素材 ID；使用 SQLite 原子领取，配置变更时在浏览器启动前停下；客户端中断的创建中任务转待核查。
- `desktop/src/main/qianchuan_plan.ts`：抖音发布成功后异步建任务；每分钟核对待执行和待素材任务；复用千川账户进程锁，避免与 Step 17 同账户并发操作；调用专属 Chrome 浏览器。自动计划账户默认关闭。
- `engine/qianchuan_plan_browser.py`：临时打开一个计划标签，结束后关闭；只在账号、商品、预算、素材、计划名均能唯一识别并回读时点击一次发布按钮。页面选择器不匹配会在提交前失败；已尝试提交却未得到唯一远端计划 ID 会停在待核查。
- `desktop/src/renderer/src/components/QianchuanPlanView.vue`：按千川账户配置预算、来源、优惠券、AIGC 和自动开关；显示任务及人工核查入口。

## 当前验证结论

- 隔离 SQLite 测试覆盖重复触发、禁用/配置变更、同账号同商品素材、提交后结果不明、异常恢复和安全重排。
- 客户端 TypeScript 类型检查与 Electron/Vite 构建通过。
- **尚未完成真实千川付费发布验收**：录屏只展示人工创建流程和最后“发布计划”按钮，未展示点击后的成功回执或远端计划 ID；两份截图分属不同广告主账户。主页作品与 Step 17 素材在计划选择器内的完整 DOM、远端创建回执仍须用合格测试账户校准。
- 2026-11-06 当前本机发布记录 #45（账号 6）没有千川档案绑定；档案 3 绑定账号 5 的广告主 ID `1875414412067016`，但其 Chrome 专属页面当前显示广告主 ID `1879582387470400`。账号 5 没有合格已发布测试记录。因此本轮没有触发真实付费计划发布。

## 真实验收顺序

1. 在客户端账号管理确认“抖音账号 → 唯一千川档案”的绑定，打开该档案专属浏览器，页面顶部广告主 ID 必须与档案一致。
2. 在千川管理里为该账户填写日预算、选择视频来源，再启用自动计划。业务测试应先采用允许的最低小额预算；金额由账户负责人决定，客户端不代填。
3. 使用该账号发布一个新的测试商品作品。主页作品来源须在千川“我的视频”可见；本地 MP4 来源须先完成 Step 17 上传并取得远端素材 ID。
4. 观察计划任务从“待执行/等待素材”进入“创建中”，在千川后台核对确有**一条**同商品同预算计划，记录远端计划 ID、状态和投放账户。
5. 再次触发相同发布通知，确认不创建第二条计划。模拟发布后回执不明，确认任务停在“待核查”且不会自动重复点击；人工核实后补录远端计划 ID 或注明不存在再重排。

真实验收未通过前，不把本实现标记为已可无人值守投放。多台电脑各自使用 SQLite，唯一约束仅覆盖本机；跨电脑同广告主同商品的全局去重需要后续中心服务端原子登记。
