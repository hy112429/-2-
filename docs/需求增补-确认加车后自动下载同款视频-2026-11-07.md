# 确认加车后自动下载同款带货视频

日期：2026-11-07。来源：用户确认“选品最终加入选品车”与商品 ID 下载视频重叠执行；选品用哪个百应账号，下载就用哪个账号并自动分类。

## 当前流程

1. 软件收到百应明确的 `cartAdded=true`，且该商品在本机选品登记结算为 `ADDED` 后，直接取回该账号 ID、商品 ID 和百应推广 ID。跳过、拒绝、结果不明及登记未结算的商品不触发下载。
2. 主进程异步读取该账号专属 Chrome 的百应「带货内容」，按该账号设置的每商品额度获取同款带货作品。下载状态、不同内容数、错误及下次重试时间落入本机数据库；客户端重启后续做。下载与后续商品详情图转视频、发布流程并行；同账号多个商品依次下载，避免同时打开大量商品页。
3. 已在素材库登记为同账号、同商品 `web_download` 且文件仍存在的视频 ID 不重复下载。候选按视频源去重，下载后按文件内容去重；遇到不同 ID 对应同一视频时继续尝试后续候选。新增 MP4 存入账号下载路径下的 `{日期}/{商品ID}/{商品ID}_{视频ID}_{序号}_{时间戳}.mp4`；未设置账号路径时，账号路径为 `{全局下载根目录}/账号-{账号ID}`。
4. 抖音作品确认 `published` 后，P-33 先等待同商品正在进行的加车下载，再优先把已下载且符合 Step 17 资格的素材加入千川队列。商品目标是该账号下载额度与 Step 17 每品额度的较小值，实际入队还受当日账号及分组额度约束。入队只是「等待上传与核对」；每次远端结果返回后按不同素材 ID 重算，不足时自动查找未用候选补位，达到目标才标为完成。结果不明的任务保留额度并待核查，不盲目补传。旧商品没有百应下载状态时仍保留千川授权查询备用路径。`submitted_review` 不触发 Step 17。
5. 下载失败不回滚已确认的加车。页面显示待重试或候选耗尽原因；千川上传仍受原有账号绑定、发布确认、额度和素材资格规则约束。平台审核及素材评估与上传成功分别展示；自动只读取判定，不把「搬运」直接推断为本地移动水印。

## 旧浏览缓存与停用账号

- 商品查询页优先遵守已确认的选品登记、加车和发布记录。其归属账号停用时，不自动换号下载。
- 仅有百应浏览缓存的商品尚未确认由哪个账号选品。若缓存账号已停用，优先匹配当前已打开该商品页的启用账号专属浏览器；没有匹配页面且仅有一个启用账号时，用它自己的百应登录态尝试读取并将下载素材归到该账号。多个启用账号而无法判断时停止，不猜测归属。
- 这一路径不需要千川开放平台 OAuth 授权，但仍需下载账号的百应登录态。旧缓存的推广 ID 只是定位商品的线索；是否能取到视频以该账号实际页面响应为准。
